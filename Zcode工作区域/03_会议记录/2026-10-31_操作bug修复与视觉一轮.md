# 会议记录：操作 bug 修复 + 视觉第一轮（2026-10-31 晚）

> 参与者：用户 + ZCode。上游文档：`02_技术方案/本轮修复与视觉方案.md`。

## 用户反馈原始问题（5 条）
1. 开场外婆对话，点对话框没反应，只有键盘 E 有反应。
2. 房间里 WASD 和屏幕摇杆都无法移动。
3. 工程里打开地图一直报错。
4. 房间太大，要缩小。
5. 地板纹理单一；村子里草地单一，希望噪声散布多种材质。

## 排查与结论

### 问题1（对话点不动）→ 已修复
- 根因：气球脚本只认 `interact` 动作，输入映射无鼠标/触摸绑定；气球是全屏控件吞掉所有点击。
- 修复：`dialogue_balloon.gd` 的 `_on_balloon_gui_input` 增加鼠标左键=推进/跳过（只认 MouseButton，
  防 PC 上"鼠标+模拟触摸"双事件一笔点两下；手机经 emulate_mouse_from_touch 同样生效）。
- 复现脚本：`tests/repro_user.tscn`（连点 6 下讲完开场对话）。

### 问题2（房间不能动）→ 已修复
- 根因：`player.gd` 的 `spawn_point` 没 `@export`，烘焙场景存不进去 → 运行时默认 (0,0)，
  开场结束把玩家传进上墙（墙体 y:-16~80 横贯全屋）→ 卡死动不了。
- 修复：`spawn_point` 加 `@export`（烘焙时序列化进 tscn），重烘焙生效。
- **教训（新踩坑）**：烘焙场景依赖的运行时字段必须 @export，否则 pack() 不写进 tscn；
  冒烟测试只查状态不查坐标，差点漏掉——repro 脚本已加位置断言。
- 附带发现：测试里"真实按键 0 位移"是测试脚本自身把按下/松开挤同一帧所致，键盘输入路径无问题。

### 问题3（地图打开报错）→ 排查完毕，多层结论
1. 场景文件健康：逐节点二分到只剩根节点也不报错；runtime 冒烟全绿。
2. 报错数量与场景资源量成正比（town 333 / worldmap 458 / mountain 1366 条），
   是**无头编辑器的加载进度弹窗无法显示**的系统噪音，GUI 编辑器不受影响。
3. 用户看到红字刷屏 = 编辑器布局残留 9 个历史场景，每次启动"重新打开场景"逐个加载触发。
   已清空布局（备份：`00_思考过程/编辑器布局备份/`）。
4. `phantom_camera` 插件启用但项目从未使用（交接文档无记录），已禁用。
5. 已知无害报错保留：DM 插件 `add_theme_color_override in base 'Nil'`（§6-10）。
- 排除项（免得以后再查）：`unique_id=` 属性（4.7 烘焙格式自带）不是诱因；format=4 不是诱因；
  UID 引用完好；town_tiles.tres 单开无错。

### 问题4（房间缩小）→ 已实施（用户拍板 16×10 + 2倍变焦）

# 第二轮（同日深夜）：用户实测反馈 3 问题

## 1. 初始房间看不到玩家 → 已修复
- **根因**：`home_root.gd` `_run_intro` 第2步 `player.visible = false`（藏人）之后，第3步只做了
  `modulate.a` 淡入，**忘了恢复 `visible = true`** → 走完整开场的玩家全程隐形。
- 为什么之前没发现：验收截图脚本预设了 `intro_wake_done` 跳过开场（不走藏人分支）；冒烟测试不断言可见性。
- 修复 + 回归：repro 新增 3 条断言（可见/淡入完成 a≥0.99/出生点）。

## 2. 村子里房子盖住玩家 → 已修复（上网核实标准做法）
- **根因两条**：① town 的 World 及其子容器（Buildings/Trees/Fences/NPCs…）**全都没开 y_sort_enabled**
  （worldmap 反而开了）→ 节点按树序绘制，排序错乱；② 房子碰撞盒底比贴图底（门垫台阶）高 10px，
  玩家能站进台阶区，但脚底 y 排在房子之前 → 被房子盖住。
- **标准做法**（godotengine#12339 / Godot 论坛 / docs）：父链每一层都开 `y_sort_enabled`；
  每个物体的排序原点对齐"脚底/墙脚"；z-index 统一 0。
- 实施：`town_build.build()` / `worldmap_build.build()` 给 World+全部子容器开 y_sort；
  `_place_houses` 碰撞盒下延到贴图底（台阶区不可站，符合直觉）。树/栅栏原点本来就是脚底，无需改。
- 验收截图 `验收截图_房前贴脸.png`：玩家紧贴台阶完整可见。

## 3. 对话字太小 → 已参数化（用户自助调节）
- `dialogue_balloon.gd` 新增检查器分组 **"对话显示（用户可调）"**：
  - `font_size` 字号（默认 12；点阵字体 **12 的整数倍最锐利**：12/24；16、20 轻微虚边）
  - `line_separation` 行间距（默认 2，0~16）
  - `panel_height` 面板高度（默认 132；字号调大后记得调大，否则文字挤出面板）
- **自助调节方法**：Godot 编辑器 → 文件系统面板双击 `scenes/ui/dialogue_balloon.tscn` →
  选中根节点 DialogueBalloon → 检查器"对话显示"组改数字 → Ctrl+S 保存。无需重烘焙，改完直接跑游戏生效。

## 验收（第二轮）
- 冒烟 73/73 PASS ×1；repro 全 ok（含 3 条新可见性断言）。

# 第三轮（同日深夜）：上帝模式（用户钦定的调试功能）

## 需求
按 P 键开关；右上角常驻按钮显示状态（点击也可切换）；开启后进任何房间/地点/地图不受剧情限制，
方便用户把所有场景过一遍。

## 实现（7 处）
1. **输入映射**：新增 `god_mode` 动作 = P 键。**P 原本绑在"暂停"上，已让出**（暂停现在只剩 Esc）。
2. **Game.gd**：`god_mode` 会话级开关（不入存档，重启默认关）+ `toggle_god_mode()`
   （开启即补调试物资：石子x99 / **火柴x99**（山道隧道黑暗机制用）/ 饼干x9，并发通知）。
3. **HUD**：右上角 `GodButton`（物品计数左侧），文案"上帝 关/开"，开启时绿色描边；点击切换；
   `_process` 里监听 P 键。按钮在触屏层之外，**手机上也常驻可点**。
4. **LocationGate**（世界地图闸门）：`unlock_flag` 检查在上帝模式下短路 → **火山口等全部闸门直接进**。
5. **StoryZone**（剧情触发区）：上帝模式下不触发（intro 独白/山道灯亮演出等不再打断看场景）。
6. **office_root**：三扇白门（门禁解谜）在上帝模式下自动移除 → 大厅/三房间/真相三件套/红门/电台直达。
7. **player.take_damage**：上帝模式无敌（野猪/低飞鸟/落石不掉血）。

## 明确没动的（剧情资产，零硬编码原则）
- 对话文件内部的剧情条件（电脑门禁对话、电台需 reveal_done 等）没改——但物理通路全开：
  上帝模式下 上山→办公区→矿车站台→空镇→镇公所（置 reveal_done）→电台 全程可走，
  想看结局演出按正常交互即可，只是不用再解谜/找火柴/绕路。
- 死亡重载、存档逻辑不变。

# 第四轮（同日深夜）：编辑器爆红解释 + 山道重修成现代公路 + 火山口密码大门

## 1. 编辑器爆红（1366条红字）→ 定性：引擎已知无害报错
- 用户截图：打开 mountain_road.tscn 时输出面板刷 `Attempting to parent and popup a dialog that
  already has a parent.`。上轮结论"GUI 不受影响"**修正**：GUI 编辑器同样刷（条数∝场景资源量）。
- **定性**（上网核实）：Godot 引擎已知问题——加载/导入时"进度弹窗被复用"，每 tick 尝试 popup 报一条。
  官方 issue godotengine#77426、4.1 dev 日志原话 "mostly harmless error spam"。**不是场景损坏**。
- 佐证：runtime 冒烟 73/73 全绿；main.tscn（小场景）0 条；报错数 mountain 1366 > worldmap 458 >
  town 333 > home 8，纯随资源量线性。
- **缓解建议（给用户）**：①退出编辑器前关掉不用的大场景标签（启动时会恢复它们）；②看到红字先跑游戏
  验证（能跑=无害）；③彻底根治只能等引擎版本更新（不建议现在升版本，4.7.2 是项目基线）。

## 2. 山道重修成"现代高速公路"（用户：参考真实公路，如海南环岛高速）
